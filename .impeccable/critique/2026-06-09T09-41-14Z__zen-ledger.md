## Cognitive Load Assessment

**One decision point exceeds 4 visible options:** The Stream advanced filter panel exposes 7 filter fields simultaneously when open. Progressive disclosure helps (collapsed by default), but when open, the density contradicts the "calm over alarm" principle.

**Settings page is a cognitive overload zone.** Profile, wealth audit, categories, recurring templates (with a full add form), data management, and app info all appear on one scrollable page with no section anchoring or progressive grouping.

---

## Emotional Journey

**The app feels calm.** Warm oat backgrounds, sage/terracotta accents, gentle copy, and the StatusRing as a reassuring daily ritual all reinforce the "lower heart rate" goal.

**Emotional valleys:**
1. Settings page — wall of forms, "Reset Application" button with red trash icon is jarring
2. AuthModal — standard modal with Google OAuth branding, emotionally flat
3. Insight page with 0 transactions — empty state is good but transition to data may feel abrupt

**Peak moment:** The InputPill capture flow. Type "Coffee 5," hit enter, get a toast. The 800ms processing delay with three-dot bounce animation creates anticipation that pays off.

---

## What's Working

1. **InputPill is the product's heartbeat.** @/# autocomplete, word-selection tagging, progressive extras panel, FAB protruding from bottom nav — genuinely effortless capture flow.

2. **StatusRing + daily status sentence.** Visual progress ring with human-readable sentence turns a budget tracker into a calm daily ritual.

3. **The color palette and design system.** Zen palette is genuinely distinctive. "Calm Money Rule" enforced consistently. Noise overlay adds subtle paper texture.

## Priority Issues

### [P1] Contrast failures in light mode
**What:** zen-herb (#A5A58D) on zen-oat (#F4F1EB) has ~2.82:1 contrast — fails WCAG AA 4.5:1. zen-nav-inactive (#8F9078) on zen-oat has ~2.66:1 — inactive nav labels invisible.
**Why it matters:** Low-vision users cannot read secondary text or inactive navigation. Fundamental accessibility failure.
**Fix:** Darken zen-herb to ~#8A8A6E or use zen-sage for secondary text. Update zen-nav-inactive token.

### [P2] AuthModal breaks design language
**What:** Uses raw SVG icons instead of Icon.svelte, standard border styling instead of Zen pill/chip vocabulary, bg-black/50 backdrop instead of bg-zen-oat/50.
**Why it matters:** Looks like it belongs to a different app. Breaks visual consistency.
**Fix:** Replace raw SVGs with Icon.svelte. Restyle to use rounded-zen, shadow-zen-soft, oat backdrop. Make Google button monochrome.

### [P2] Modal accessibility gaps
**What:** AuthModal lacks focus trap — Tab escapes into background. Close buttons (20x20px) are icon-only with no aria-label.
**Why it matters:** Keyboard and screen reader users cannot use the auth flow properly.
**Fix:** Add focus trap. Add aria-label to close buttons. Size close buttons to 44x44px minimum.

### [P2] WealthLedger gradient drifts from palette
**What:** bg-gradient-to-br from-zen-sage to-zen-herb with abstract blur blobs is the most "AI-generated" visual element.
**Why it matters:** Contradicts "Digital Softness" principle of unbleached paper and flat tonal surfaces.
**Fix:** Use solid sage background with subtle noise texture, or zen-surface/40 + backdrop-blur pattern.

### [P3] Settings uses alert() instead of Toast
**What:** alert("Profile updated!") and alert("Data imported successfully!") break the calm experience.
**Why it matters:** Browser-native interruptions are jarring in an otherwise gentle interface.
**Fix:** Import and use the Toast store already in the layout.

## Technical Issues (from Assessment B)

### [P1] Touch target failures
- Passthrough toggle is 24x44px — fails 48x48px minimum (InputPill.svelte:448-454)
- Modal close buttons are 20x20px — fails minimum (AuthModal.svelte:59, 98)

### [P2] SyncButton tooltip invisible on mobile
- Uses onmouseenter/onmouseleave — never appears on touch devices (SyncButton.svelte:37-38)

### [P2] Sync engine performance
- Pushes items sequentially in for loop — N+1 writes (engine.ts:71-89)
- Remote pull fetches all records with .select('*') — no pagination (engine.ts:98-102)

### [P2] Icon.svelte uses Svelte 4 syntax
- export let and $: reactive declarations instead of Svelte 5 $props() (Icon.svelte:4-10)

## Minor Observations

- confirm() dialogs in TransactionCard use browser-native styling — would benefit from custom confirmation sheet
- Voice recording simulation hardcodes "Coffee at Starbucks $5" — fine for dev, noted as stub
- Noise overlay z-index 9999 may interfere with review sheet (z-101) and mobile drawer (z-50)
- Insight story card carousel uses aspect-[4/5] — may feel tall on narrow mobile screens
- TransactionCard re-computes settlements by scanning ALL transactions for each card — performance concern

## Questions to Consider

1. **What would a confident version of Settings look like?** Could recurring templates be its own route, like Purposes and Parties?
2. **Does the WealthLedger need a hero card at all?** The summary statement already tells the story. What if wealth overview were a calm sentence instead of a gradient banner?
3. **Should the "or" divider in AuthModal exist?** Magic link and Google sign-in feel like two different mental models. Could one be default and the other "Also available"?
